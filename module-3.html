Data Visualization & Storytelling

Tableau or Power BI, and the UX judgment that separates a chart from a dashboard someone can actually use in 30 seconds.

Core concepts

  • Chart selection: when a line, bar, or table beats a fancier alternative (usually: often).
  • Dashboard UX: one primary "so what" per view, filters that don't overwhelm, clear hierarchy.
  • Live data: connect a real source (CSV, SQL result) rather than pasting static numbers.
  • Annotating: every chart in a portfolio piece needs one sentence of interpretation next to it.

Interview questions for this module

"How do you decide what chart type to use for a given dataset?"

Model answer: start from the question, not the data. Comparing categories → bar. Trend over time → line. Part-to-whole → stacked bar (rarely pie). Relationship between two numeric variables → scatter. Precise individual values → a table beats a chart.

"Walk me through how you'd design a dashboard for a CMO who has 30 seconds to look at it."

Model answer: lead with 3–4 KPI tiles above the fold, each with a trend arrow, no more than one chart requiring interpretation, and a single annotation stating what changed and why it matters — the CMO should never have to ask "so what should I do with this."
