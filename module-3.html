Tableau or Power BI, and the UX judgment that separates a chart from a dashboard someone can actually use in 30 seconds.

Beginner

Core concepts

  • Chart selection: when a line, bar, or table beats a fancier alternative (usually: often).
  • Dashboard UX: one primary "so what" per view, filters that don't overwhelm, clear hierarchy.
  • Live data: connect a real source (CSV, SQL result) rather than pasting static numbers.
  • Annotating: every chart in a portfolio piece needs one sentence of interpretation next to it.

Intermediate

Making the tool do more of the thinking

  • Calculated fields: a formula built inside the BI tool (e.g. ROAS = SUM(Revenue) / SUM(Spend)) so it recalculates correctly at any level of aggregation, instead of averaging a pre-computed ROAS column (which silently produces the wrong number).
  • Table calculations: running total, % of total, % change vs. previous period — computed by the tool over the chart's current view, so it stays correct as filters change.
  • Parameters & filters: a parameter lets a viewer swap what metric a chart shows (e.g. toggle between Spend / Revenue / ROAS) without you building three separate charts.
  • Small multiples: the same small chart repeated once per channel/segment, side by side — often clearer than one crowded chart with 6 overlapping lines.

Structuring a portfolio case study: SCQA

When you present Portfolio Project 3 in an interview, structure the narrative with the consulting-standard SCQA framework instead of walking through your process chronologically:

Situation — the business context, one sentence. Complication — what's wrong or uncertain (the CAC jump, the underperforming channel). Question — the one question your analysis answers. Answer — your recommendation, stated first, with the supporting data available if asked. This is also called the Pyramid Principle: conclusion first, evidence on demand — the opposite instinct from "let me walk you through my SQL."

Interview questions for this module

"How do you decide what chart type to use for a given dataset?"

Model answer: start from the question, not the data. Comparing categories → bar. Trend over time → line. Part-to-whole → stacked bar (rarely pie). Relationship between two numeric variables → scatter. Precise individual values → a table beats a chart.

"Walk me through how you'd design a dashboard for a CMO who has 30 seconds to look at it."

Model answer: lead with 3–4 KPI tiles above the fold, each with a trend arrow, no more than one chart requiring interpretation, and a single annotation stating what changed and why it matters — the CMO should never have to ask "so what should I do with this."

"How do you present analysis findings to a non-technical audience?" (real, sourced)

Model answer: lead with the recommendation (SCQA/Pyramid Principle), not the method — "We should shift budget from X to Y because Z," then offer the analysis behind it only if asked.
