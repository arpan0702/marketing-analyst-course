The Transition Mindset & Analytics Foundations

Reframe what "analysis" means before touching a single tool. Marketing judgment already contains most of the reasoning an analyst uses — this module names it.

Beginner

Start here: what "being an analyst" actually means day-to-day

Strip away the job title and an analyst does one thing on repeat: someone has a question ("why did signups drop?"), the analyst finds data that can answer it, cleans that data until it's trustworthy, looks for the pattern, draws it so someone else can see the pattern too, and recommends what to do about it. That's the whole job. Every tool in this course (Excel, SQL, Tableau, GA4, statistics) exists only to make one of those six steps faster or more rigorous.

Core concepts

  • The analytics workflow: question → data → clean → analyze → visualize → recommend.
  • Vocabulary shift: "metric" (a number, like clicks) vs. "dimension" (a category, like channel), "grain" (what one row represents), "hypothesis," "confidence."
  • Every marketing skill has an analytical shadow — see the map below.

Exercises (do these before moving on)

  1. Pick one past campaign. Write the question you were actually trying to answer with its performance data, in one sentence.
  2. List every metric you currently pull in your job. Label each a dimension or a metric.
  3. Rewrite three resume bullets using: [analytical verb] + [what was measured] + [tool/method] + [quantified result] — before learning any tool. This proves the pivot is framing first, tools second.
Intermediate

Prioritizing when everyone wants an analysis "by Friday"

Once you're producing real analysis, the job shifts from "can I do this" to "what do I do first." Marketing teams generate more analysis requests than one analyst can serve — the skill is triaging them defensibly, not silently working overtime.

  • ICE scoring: Impact × Confidence ÷ Effort. Quick, good for ranking a backlog of ad-hoc requests.
  • RICE scoring: Reach × Impact × Confidence ÷ Effort. Adds "how many people/campaigns does this touch" — better when requests vary wildly in scope.
  • The "so what" test: before starting any analysis, write the sentence you expect to end with ("we should shift budget from X to Y"). If you can't imagine a sentence that would change a decision, the analysis isn't worth doing yet.

Advanced

The analytics maturity model — and knowing which level you're operating at

Interviewers at the 2-year mark expect you to know where a given piece of work sits on this ladder, and to be honest about which levels you can currently deliver:

  1. Descriptive — "what happened" (a dashboard, a report). Most of Modules 1–4.
  2. Diagnostic — "why it happened" (funnel breakdowns, cohort analysis, the CAC-jumped-30% case pattern).
  3. Predictive — "what will happen" (forecasting, LTV modeling — touched in Module 5's advanced tier).
  4. Prescriptive — "what to do about it" (budget reallocation recommendations backed by a test, not just a hunch).

Most real marketing-analyst work lives at levels 1–2, with occasional forays into 4 when a recommendation is well-supported. Claiming level 3–4 fluency you don't have is a common overreach that gets caught fast in a technical screen — better to be precise about what you've actually done.

Biases that quietly wreck an analysis

Confirmation bias — building the query to find what you already expected. Counter it by writing the "so what" sentence before looking at the data, then checking if the data actually supports it.  Survivorship bias — analyzing only customers who converted/stayed, missing what churned/bounced customers looked like.  Simpson's paradox — a trend that holds in every individual segment can reverse when segments are combined (e.g. overall conversion rate drops even though it rose in every channel, because mix shifted toward a lower-converting channel). Always check a segment breakdown before trusting an aggregate trend.

Interview questions for this module

"Walk me through how you'd approach a completely new dataset you've never seen before."

Model answer: start with the grain (what does one row represent?), check for obvious data quality issues (nulls, duplicates, date ranges), then re-state the business question before writing a single query — most bad analysis comes from skipping this and jumping straight to a pivot table.

"What's the difference between a metric and a dimension?"

Model answer: a metric is a number you aggregate (revenue, clicks, sessions); a dimension is a category you group or filter by (channel, region, device). Every chart or query is really "which metric, sliced by which dimension."

"How do you decide which metrics to prioritize when evaluating a marketing program?" (real, sourced — see the Interview Bank)

Model answer: anchor to the business goal one level up, pick 1–2 primary metrics that goal implies, treat the rest as diagnostic. A dashboard where everything is "important" has no priority at all.
