Beginner

Start here: what a cell and a formula actually are

A spreadsheet is a grid. Every box in that grid — a cell — has an address made of its column letter and row number: the cell in column B, row 2, is called B2. A formula is anything you type into a cell starting with = — it tells the cell "don't just sit there with a fixed value, calculate this instead, and recalculate automatically whenever the cells it references change."

a cell, a reference, a formula

Relative vs. absolute references — the mistake almost everyone makes once

When you copy a formula down a column, its cell references normally shift with it ("relative"). Sometimes you don't want that — e.g. every row should divide by the same total in one fixed cell. Lock a reference with $: $C$1 stays put no matter where the formula is copied.

what happens when you copy a formula down

Relative reference (=B2*C1)         Absolute reference (=B2*$C$1)
--------------------------------    --------------------------------
Row 2:  =B2*C1                      Row 2:  =B2*$C$1
Row 3:  =B3*C2   ← C1 shifted to C2 Row 3:  =B3*$C$1   ← C1 stays locked
Row 4:  =B4*C3   ← shifted again    Row 4:  =B4*$C$1   ← still locked

Rule of thumb: if a formula is copied down and suddenly returns wrong or zero values, the first thing to check is a reference that should have been locked with $ and wasn't.

Intermediate

What a pivot table actually does

A pivot table takes a long list of raw rows (one row per transaction) and collapses it into a summary: pick a category to group by (rows), pick a number to total up (values). This is the exact same operation as SQL's GROUP BY — a pivot table is GROUP BY with a drag-and-drop interface instead of a keyword.

before → after: raw rows become a summary

Building one, step by step: select your raw data → Insert > PivotTable → a new pane appears with four boxes: Filters, Columns, Rows, Values. Drag Channel into Rows, drag Spend into Values (it defaults to Sum) — that's the entire build. Everything else (adding a second row-grouping like Month, filtering, formatting) is a variation of this same drag.

mental model bridge to Module 2

PIVOT TABLE                          SQL EQUIVALENT (Module 2)
------------------------------       -------------------------------
Rows:    Channel                     SELECT channel,
Values:  Sum of Spend         -->            SUM(spend)  AS total_spend
Filter:  Month = "June"              FROM   campaigns
                                      WHERE  month = 'June'
                                      GROUP BY channel;

GETPIVOTDATA pulls one specific number out of a pivot table into a regular cell (e.g. for a KPI tile or a sentence in a report) — Excel writes this formula automatically when you click a pivot cell from outside the pivot table.

Combining tables: XLOOKUP

A pivot table summarizes one table. To pull data from a second table by a matching key — the spreadsheet version of a SQL JOIN — use XLOOKUP: =XLOOKUP(lookup_value, lookup_array, return_array). It searches for lookup_value inside lookup_array, and returns the matching position from return_array.

(You'll also see VLOOKUP in older files — same idea, but it only searches left-to-right and breaks if columns get reordered. XLOOKUP fixes both problems; use it by default.)

Beyond a single condition

  • SUMIFS / COUNTIFS / AVERAGEIFS: sum, count, or average with multiple conditions at once — "total spend where channel = Email AND month = June" without a pivot table.
  • Nested IFs / IFS(): more than two outcomes (e.g. "High" / "Medium" / "Low" spend tiers) without stacking IF-inside-IF by hand.
  • Data validation: dropdown lists on a "channel" column prevent "Email" / "email" / "e-mail" from silently becoming three different values in a pivot table — this is the spreadsheet-side fix for the UTM-casing problem in Module 4.

Charts that don't need rebuilding every week

  • Combination charts: two chart types sharing one x-axis (bars for spend, a line for ROAS on a second axis) — the standard way to show a volume metric and a rate metric together without one dwarfing the other.
  • PivotCharts: a chart built directly on a pivot table — filter the pivot, the chart updates with it, no rebuilding.
  • Sparklines: a tiny trend line inside a single cell, next to a number — lets a table of 20 rows show a trend per row without 20 separate charts.
  • Slicers: clickable filter buttons attached to a pivot table/chart — the spreadsheet precursor to a real dashboard filter in Module 3.

Advanced

Dynamic arrays & automated reporting

  • FILTER / UNIQUE / SORT (dynamic arrays): =FILTER(range, condition) spills a live list of matching rows without a pivot table or a manual filter click — it updates automatically as source data changes.
  • SUMPRODUCT: multi-condition math without an array-entered formula — the standard way to compute a weighted average, like spend-weighted average CPA across channels, which a plain AVERAGE gets wrong.
  • Power Query / Get & Transform: import and reshape messy source files (multiple CSV exports, inconsistent headers) into a clean table on a schedule, without manual copy-paste every week — this is what "automating a report" actually means before anyone touches SQL or Python.
  • Named ranges: replace $B$2:$B$500 with Spend in formulas — makes a workbook a stakeholder can audit instead of a black box.
Challenge 6 Write a FILTER formula that returns all rows from a campaigns table where channel = "Paid Social".
Challenge 7 Write a SUMPRODUCT formula for the spend-weighted average CPA: SUMPRODUCT(spend_range, cpa_range) / SUM(spend_range).

Why not just AVERAGE(cpa_range)? A plain average treats a channel with 5 orders and a channel with 500 orders as equally important. SUMPRODUCT weights by volume — the same fix that Module 3's calculated-field ROAS problem needed.

Interview questions for this module

"How would you use a pivot table to find your top 5 campaigns by ROI?"

Model answer: rows = campaign name, values = sum of revenue and sum of spend (or a calculated ROI field), sort descending on the ROI value, filter to top 5 — then say what you'd do with that list, not just how you built it.

"What's the difference between VLOOKUP and XLOOKUP, and why does it matter?"

Model answer: VLOOKUP only searches left-to-right and breaks if columns are reordered; XLOOKUP searches in either direction, returns a clean error value, and doesn't break when columns move. Mentioning XLOOKUP by name signals current tooling, not a 2015-era spreadsheet habit.

"When would you use SUMIFS instead of a pivot table?"

Model answer: SUMIFS when you need one specific number embedded in a sentence or a KPI tile (e.g. a single cell feeding a summary dashboard); a pivot table when you need to explore or slice a full dataset interactively. They solve the same aggregation problem in different contexts.

"What's the difference between a relative and an absolute cell reference, and when do you need the absolute one?"

Model answer: a relative reference (A1) shifts when a formula is copied to another cell; an absolute reference ($A$1) stays locked. Use an absolute reference whenever every copy of a formula needs to point at the same fixed cell — a total, a tax rate, a target value.
