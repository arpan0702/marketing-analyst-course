Get the data — no Kaggle account needed

On the job, a marketing analyst pulls from GA4, an ad platform export, or a CRM — not Kaggle. For a portfolio piece, though, you need data you're allowed to publish publicly, and your employer's real numbers aren't that. So: three ready-made datasets, sized and shaped like real campaign data, one click, no login, no searching. Download all three now and reuse them across every project below.

campaign_performance.csv 90 rows — 5 channels × 3 campaigns × 6 months. Spend, impressions, clicks, conversions, revenue. Powers the ROI Dashboard capstone and the Module 1 & 3 mini-projects.
customer_orders.csv 509 orders across 180 customers, with repeat purchases and signup dates — built for RFM segmentation. Powers the Customer Segmentation capstone.
ab_test_results.csv 5,000 visitor-level rows, two variants, a real (small but genuine) lift baked in. Powers the A/B Test capstone and the Module 5 mini-project.

Want a bigger, messier dataset for a fourth portfolio piece later? Kaggle's "Online Retail II" and "Marketing A/B Testing" datasets are the standard, recruiter-recognized public sources — optional, not required to finish any project on this page.

Mini-projects — one per module

Do each one right after finishing its module, while the skill is fresh. None of these need anything beyond what that module already taught.

Module 0

Reframe your resume

Goal
Prove the pivot is framing, not tools — before touching a single technical skill.
Steps
Pick 3 real bullets from your current resume. Rewrite each with the formula: [analytical verb] + [what was measured] + [tool/method] + [quantified result]. If you don't have a real number, estimate one honestly and mark it as an estimate — don't leave it blank.
Deliverable
A before/after list of 3 bullets, saved somewhere you'll actually use it on the Resume & Apply page later.
Module 1

Build a weekly channel report

Goal
The exact spreadsheet skill a Marketing Analyst does every single week.
Dataset
campaign_performance.csv (downloaded above).
Steps
Clean it (fix blanks, standardize dates, remove duplicates). Build a pivot table: spend and conversions by channel and month. Add a second small sheet of made-up "target CPA" per channel, XLOOKUP it in, and flag any channel over target. Add one SUMIFS KPI cell and one combination chart (bars + a rate line).
Deliverable
A saved spreadsheet file with the pivot, the XLOOKUP flag column, and the chart.
Module 2

SQL audit — 8 business questions

Goal
Prove you can go from a plain-English business question to a working query without hand-holding — this is exactly what a technical screen tests.
Where
The live SQL runner already in Module 2 — no setup needed.
The 8 questions
  1. Which channel has the highest average order value?
  2. Which 3 customers have generated the most total revenue?
  3. How many distinct customers ordered in each month?
  4. Which country has the highest total revenue, and from how many customers?
  5. Find any customer who has never placed an order that shows a NULL country (data-quality check).
  6. What's the month-over-month revenue change for the "Paid Search" channel specifically?
  7. Which customers signed up but placed zero orders in their signup month (slow starters)?
  8. Using the order_items table, which single product appears in the most baskets?
Deliverable
A doc with each question, the query you wrote, the result, and one sentence on what a marketer should do with the answer.
Module 3

Rebuild one bad dashboard

Goal
Dashboard judgment is the actual skill being tested, not chart mechanics.
Steps
Find a dashboard online you think is genuinely bad (a public dashboard gallery entry, a screenshot from a "worst dashboards" blog post, or one from your current job). Identify what's wrong using this course's hierarchy (KPI tiles → trend → breakdown → detail table). Rebuild the single worst chart from it in Power BI Desktop (free), loading campaign_performance.csv as your data source, following the hierarchy properly.
Deliverable
A screenshot of the "before," a screenshot of your rebuild, and a 3-sentence written critique of what changed and why.
Module 4

UTM governance doc + one real GA4 finding

Goal
Prove you can think about tracking architecture before a launch, not just react to broken data after.
Steps
Write a one-page UTM naming convention doc for a hypothetical 3-channel launch (paid social, email, paid search) — casing rule, separator rule, a fixed list of allowed utm_medium values. Then open Google's public GA4 demo property ("Google Merchandise Store"), find the Explorations funnel report, and identify one real drop-off point.
Deliverable
The naming convention doc, plus a screenshot of the funnel with 2 sentences on what the drop-off suggests.
Module 5

A/B test read-out memo

Goal
The actual deliverable a marketing analyst produces after a test ends — a decision memo, not a stats homework answer.
Dataset
ab_test_results.csv (downloaded above) — Variant A vs. Variant B, 2,500 visitors each.
Steps
Calculate each group's conversion rate. Run it through this course's significance calculator (or a chi-square function in Sheets) to get a z-score and p-value. Check whether the sample size was actually large enough using this course's sample-size calculator, retroactively.
Deliverable
A one-page memo: the result, whether it's significant, a ship/no-ship recommendation, and one caveat about the sample (size, duration, or representativeness).

The 3 capstone portfolio projects

These are the pieces that go on your resume and LinkedIn, and the ones you present in a case-study interview round. Build them in order — each is meant to take about 1–2 weeks alongside the module you're on, per the Roadmap.

Capstone 1 — Weeks 8–9

Customer Segmentation Analysis

Dataset
customer_orders.csv (downloaded above) — 509 orders, 180 customers, real repeat-purchase patterns already built in.
Build it with
Module 1 (pivot exploration) + Module 2's RFM/NTILE technique (Advanced tier) for the actual scoring + Power BI for the visual.
Steps
  1. Open it in Excel/Sheets first — sanity-check it with a pivot table (revenue by country, orders by month) before touching SQL.
  2. Load it into a SQL environment (or extend this course's Module 2 database with your own tables) and compute Recency, Frequency, Monetary per customer.
  3. Score each with NTILE(4), exactly as taught in Module 2, and combine into segment codes.
  4. In Power BI Desktop: Get Data → Text/CSV, load your scored output, and build one bar chart of customer count per segment plus one bar chart of average revenue per segment.
  5. Write the narrative — this is the actual deliverable, not the query.
The narrative to write
"I identified that X% of customers drive Y% of revenue and recommend a retention campaign for the next-highest-value segment." Run the numbers on this exact dataset and use your real X/Y — that's the deliverable, the SQL is how you earned the right to say it.
Publish it
A Power BI screenshot (segment chart + RFM table) plus a 3–4 sentence narrative, on a doc or simple webpage. Link it from your resume.
Capstone 2 — Weeks 10–11

A/B Testing & Conversion Rate Optimization

Dataset
ab_test_results.csv (downloaded above) — 2,500 visitors per variant, visitor-level, with device.
Build it with
Module 5 in full — significance calculator, sample-size calculator, the peeking/multiple-testing warnings.
Steps
  1. State the hypothesis and success metric before looking at results (Module 0's "so what" test, applied for real).
  2. Calculate conversion rate per group (pivot table or SQL: COUNT conversions ÷ COUNT visitors, grouped by variant). Plug the two rates into Module 5's significance calculator to get a z-score and p-value.
  3. Segment the result by device — check whether the effect holds on both desktop and mobile or is concentrated in one.
  4. Build one Power BI bar chart: conversion rate by variant, split by device.
  5. Write the ship/no-ship recommendation with the confidence level and one caveat.
What you should find
Variant A converts at roughly 5.0%, Variant B at roughly 6.4% — a real, if modest, lift that should come back statistically significant at 95% confidence (p around 0.03). Your exact numbers will differ slightly once you segment by device — that's the actual finding to write up, not the topline.
The narrative to write
"Variant B lifted conversion ~1.4 points (a 28% relative lift) at 95% confidence; I'd recommend shipping it but flag that the lift is concentrated on [device] traffic." The caveat is what separates an analyst from someone who ran a formula.
Publish it
A one-page write-up with the numbers, the Power BI chart, and the recommendation — this is the mini-project from Module 5, extended into a full narrative.
Capstone 3 — Weeks 13–14 — lead with this one

Marketing Campaign ROI Dashboard

Dataset
campaign_performance.csv (downloaded above) — 90 rows, 5 channels, 6 months, already has spend, conversions, and revenue for a real ROAS calculation.
Build it with
Everything — Module 1 (Excel sanity-check), Module 2 (SQL aggregation), Module 3 (dashboard build), Module 4 (channel/UTM thinking), Module 5 (CAC/ROAS).
Steps
  1. Aggregate spend, revenue, and ROAS by channel and month — in Excel with a pivot table first, then again in SQL to double-check yourself.
  2. In Power BI Desktop: Get Data → Text/CSV, load campaign_performance.csv directly (no cleaning needed, it's already tidy).
  3. Build a 3-view report following Module 3's hierarchy: KPI cards (total spend, revenue, blended ROAS) → a line chart of revenue by month → a bar chart of ROAS by channel → a matrix/table of campaign-level detail.
  4. Add one slicer (month) and one text-box annotation per page — the "so what," not just the number.
  5. Find the one non-obvious insight and lead the write-up with it — this dataset has one baked in: Organic Search has near-zero spend but punches far above its weight on ROAS, while Paid Search drives the most absolute revenue at a much lower ROAS multiple. That tension is your story.
The narrative to write
"Organic Search returns the highest ROAS by a wide margin but is capped on volume; Paid Search drives the most revenue at a fraction of the efficiency — I'd recommend testing a modest budget shift from Paid Search into scaling Organic content investment." This is the project you self-assigned and completed like the actual job.
Publish it
Power BI Desktop has a free Publish to web option under the Share menu — it gives you a public, embeddable link with zero hosting setup. Use that link plus a screenshot in your write-up. This is the project you open with in a case-study interview round.

Making a recruiter actually stop scrolling

A recruiter spends seconds, not minutes, on a portfolio link. The project itself being good isn't enough — how you present it is what earns the click.

  • Screenshot first, link second. Post the Power BI chart or the segment table as an image directly in the LinkedIn post — a bare link gets scrolled past; a chart with real numbers on it stops the scroll.
  • Lead with the number, not the tool. "Found a 28% conversion lift" beats "Built an A/B testing dashboard in Power BI" as an opening line — the number is the hook, the tool is a footnote.
  • One insight, not a feature list. A recruiter isn't evaluating your Power BI proficiency in the caption — they're checking whether you can find something and say it clearly. Give them one sentence, not a tour.
LinkedIn post template

[The finding, in plain numbers — no jargon] I dug into [dataset/project] to see [the question you asked]. Turns out [the counterintuitive or useful part]. Here's the breakdown 👇 [screenshot of the Power BI chart] Built with SQL + Power BI, as part of a hands-on analytics program I've been working through. Full write-up: [link]
