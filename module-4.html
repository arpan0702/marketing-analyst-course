Start here: three tools, one pipeline

GA4, GTM, and UTMs are three different things that get confused constantly. A UTM is a tag on a URL (data about where a click came from). GTM is the deployment mechanism (it fires tracking code without an engineer touching the site). GA4 is where the data lands and gets reported. One flows into the next — see the pipeline below.

tracking pipeline: click to dashboard

Core concepts

  • GA4's event model: everything is an event with parameters (not session-based, like the old Universal Analytics).
  • GTM: tags, triggers, variables — how tracking gets deployed without engineering.
  • UTM architecture: a consistent naming convention across source/medium/campaign so reporting doesn't fragment.
  • Key events (conversions), funnel/exploration reports, and DebugView for QA.

Check your understanding

Interview questions for this module

"How would you set up UTM tracking for a new campaign launch across 3 channels?"

Model answer: agree on a naming convention doc first (lowercase, underscores, a fixed list of medium values) before anyone builds a single link — most attribution reporting breaks not from missing UTMs but from inconsistent ones ("Email" vs "email" vs "e-mail" become three different rows).

"What's the difference between a GA4 event and a key event (conversion)?"

Model answer: every interaction is an event (page_view, scroll, click); a key event is an event you've explicitly marked as meaningful to the business (purchase, form submission) — the subset GA4 optimizes and reports conversions against.

"A campaign's traffic isn't showing up in GA4 — how do you debug it?"

Model answer, in order: (1) check the UTM parameters are actually present and correctly formatted on the live URL, (2) check for an ad blocker or consent-mode issue suppressing the tag, (3) open GTM's Preview mode / GA4 DebugView to confirm the trigger is firing at all before assuming it's a reporting delay.
