Beginner

Start here: three tools, one pipeline

GA4, GTM, and UTMs are three different things that get confused constantly. A UTM is a tag on a URL (data about where a click came from). GTM is the deployment mechanism (it fires tracking code without an engineer touching the site). GA4 is where the data lands and gets reported. One flows into the next — see the pipeline below.

tracking pipeline: click to dashboard

The vocabulary, from zero: pageview, session, event, conversion

One visitor lands on a page, scrolls, clicks a button, and submits a form. Every one of those actions is an event — even loading the page counts as one (page_view). All the events from one visit, bundled together, form a session. If one of those events matters enough to the business to count as a win — a form submit, a purchase — you mark it as a key event (GA4's word for what everyone still colloquially calls a "conversion").

Core concepts

  • GA4's event model: everything is an event with parameters (not session-based, like the old Universal Analytics).
  • GTM: tags, triggers, variables — how tracking gets deployed without engineering.
  • UTM architecture: a consistent naming convention across source/medium/campaign so reporting doesn't fragment.
  • Key events (conversions), funnel/exploration reports, and DebugView for QA.

Intermediate

Beyond pageviews: tracking what actually matters to the business

  • Enhanced ecommerce events: view_item, add_to_cart, begin_checkout, purchase — GA4's built-in vocabulary for a purchase funnel, so you're not inventing custom event names for standard behavior.
  • Custom dimensions & metrics: GA4 doesn't know your business's specific concepts (loyalty tier, lead source) until you register them as custom dimensions — otherwise that data arrives as an event parameter but never becomes a usable report column.
  • Audiences: a saved segment definition (e.g. "added to cart but didn't purchase in 7 days") reusable across reports and exportable to Google Ads for remarketing — the bridge between analytics and media buying.
  • GA4 + Google Ads linking: without this link, Ads campaign performance and GA4 on-site behavior live in two disconnected systems — linking is what makes an "assisted conversions" or full-funnel view possible at all.
  • Consent Mode: when a visitor declines cookies, GA4 models (statistically estimates) the missing conversions rather than showing zero — worth knowing this exists so a sudden regional dip doesn't get mis-diagnosed as a real drop.

Advanced

Attribution modeling & where the real edge cases live

Worth knowing before this comes up GA4 defaults to data-driven attribution (DDA), but DDA needs roughly 300–400 monthly conversions on a specific conversion event to compute reliably. Below that threshold, GA4 silently reverts to a last-click-style model — with no warning anywhere in the UI. On a lower-volume conversion event, check this explicitly before trusting an attribution report.
  • Multi-touch vs. last-touch: multi-touch models (linear, time-decay, data-driven) better credit mid-funnel channels like content and email that warm a prospect up before the final click; last-touch is reasonable for channels where the final decision genuinely is that channel's work, like branded paid search.
  • Server-side GTM: instead of the browser sending tracking data directly to every vendor (Google, Meta, etc.), the browser sends it once to a server you control, which forwards it onward — improves data accuracy against ad blockers and gives you a single point to filter/enrich data before it leaves your system. You won't set this up as a marketing analyst, but you should recognize the term when a data/eng team mentions it.
  • Cross-domain tracking: if a checkout lives on a different domain than the main site, GA4 needs to be explicitly configured to pass the client ID across that domain boundary, or every checkout session gets counted as two separate sessions from two "different" visitors.
  • Reconciling GA4 vs. CRM vs. ad platform numbers: these will never match exactly, and that's expected — different attribution windows, client-side tracking loss (ad blockers, iOS ITP/Safari ITP), and ad platforms self-reporting more generous attribution than GA4's model all contribute. Pick one source of truth per decision and say which, rather than trying to force all three into agreement.

Interview questions for this module

"How would you set up UTM tracking for a new campaign launch across 3 channels?"

Model answer: agree on a naming convention doc first (lowercase, underscores, a fixed list of medium values) before anyone builds a single link — most attribution reporting breaks not from missing UTMs but from inconsistent ones ("Email" vs "email" vs "e-mail" become three different rows).

"What's the difference between a GA4 event and a key event (conversion)?"

Model answer: every interaction is an event (page_view, scroll, click); a key event is an event you've explicitly marked as meaningful to the business (purchase, form submission) — the subset GA4 optimizes and reports conversions against.

"A campaign's traffic isn't showing up in GA4 — how do you debug it?"

Model answer, in order: (1) check the UTM parameters are actually present and correctly formatted on the live URL, (2) check for an ad blocker or consent-mode issue suppressing the tag, (3) open GTM's Preview mode / GA4 DebugView to confirm the trigger is firing at all before assuming it's a reporting delay.

"How would you build a marketing attribution model when you have incomplete data across channels?" (real, sourced)

Model answer: state the limitation up front, then triangulate — use GA4's multi-touch view where available, supplement with a lift/holdout test for channels attribution can't see well (brand, offline), and be explicit about which channels' numbers you trust and which you don't.

"How do you reconcile GA4 numbers that don't match your CRM or ad platform reports?" (real, sourced)

Model answer: this is expected, not a bug — different attribution windows, client-side tracking loss, and ad platforms self-reporting generously all contribute. Pick a source of truth per decision and say which, rather than trying to make all three numbers agree.
