Start here: what a database actually is

A database is just a set of spreadsheets (called tables) that can talk to each other. Each table has columns (like a spreadsheet's headers) and rows (one row = one thing — one order, one customer). SQL is the language for asking that set of tables a question. Everything below — SELECT, JOIN, GROUP BY — is one type of question.

Core concepts

  • SELECT, WHERE, ORDER BY, LIMIT — basic retrieval.
  • JOIN (INNER, LEFT) — combining an orders table with a customers table.
  • GROUP BY + aggregations (SUM, COUNT, AVG) — the pivot table, formalized.
  • Window functions (RANK(), LAG()) — rank within a group, month-over-month change.
  • CASE WHEN for segment bucketing.

Interview questions for this module

"Write a query to find the top 3 campaigns by conversion rate in each region."

Model answer: use RANK() OVER (PARTITION BY region ORDER BY conversion_rate DESC) in a subquery, then filter the outer query to rank <= 3. Partitioning is the key idea — it resets the ranking within each region instead of across the whole table.

"What's the difference between INNER JOIN and LEFT JOIN, and when would a marketing analyst care?"

Model answer: INNER JOIN only keeps rows with a match in both tables; LEFT JOIN keeps every row from the left table even without a match. A LEFT JOIN matters for churn or inactivity analysis — you need customers with zero orders to show up, not disappear.

"How would you find month-over-month percent change in spend using SQL?"

Model answer: LAG(spend) OVER (PARTITION BY channel ORDER BY month) to get the prior month's value in the same row, then compute (spend - prior_spend) / prior_spend.
